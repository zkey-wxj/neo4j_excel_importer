## 一、目标与体验指标

| 维度 | 现状 | 目标 |
|------|------|------|
| 首屏可读性 | 数据到达后视角不动，节点从屏幕外飞入，用户看到空白/散点 | 首屏 400ms 内自动框选全图，内容铺满视口 |
| 标签可读性 | 固定阈值 `k>0.6` 全量显示，字号恒定 11px | 分级 LOD，放大有反馈，密集区自动让位 |
| 放大反馈 | 节点变大但文字不变，视觉"没反应" | 文字随缩放温和增长（11px → 16px） |
| 加载感知 | 只有一个转圈 spinner | 确定性进度条 + 节点错峰入场 + 相机软跟随 |
| 1000 节点帧率 | 全量描边/箭头/标签，每条边一次 `stroke()` | LOD 剪枝 + 批量 stroke，≥50fps |
| 10000 节点 | 基本不可用 | reduced 模式 + 点云 LOD，可交互 |

## 二、现状诊断（含代码定位）

### 1. 标签阈值是"全局硬编码"，且与"视口密度"无关

`useGraphCanvas.js:561`（节点）与 `:447`（边）：

```js
if (k > 0.6) { ...节点标签... }      // 节点标签：k > 0.6
if (edge.name && k > 0.7) { ...边标签... }  // 边标签：k > 0.7
```

问题：只有"开/关"两态，没有中间层级；阈值只看缩放 `k`，不看**当前视口里有多少节点**。
同样 `k=0.7`，稀疏图（20 个节点）本该显示标签，密集图（2000 个节点）必须隐藏——现在两者行为一致。

### 2. 标签字号恒定，放大不给反馈

`useGraphCanvas.js:589`（节点）、`:455`（边）：

```js
const fs = sf ? Math.max(12, 12 / k) : Math.max(11, 11 / k)  // 节点
const fs = Math.max(9, 9 / k)                                 // 边
```

`fs` 是世界坐标字号，屏幕上显示为 `fs * k = max(11k, 11) ≈ 11px`（k≥1 时恒为 11px）。
结果是：k 从 1 放大到 4，节点半径从 10px 长到 40px，文字始终 11px —— 节点把文字"吃掉"了。

### 3. 无遮挡剔除，标签互相碾压

标签固定绘制在 `x + r + 5/k`（节点右侧），没有占位检测。缩放 0.6~1.0 区间内，
标签矩形互相覆盖是常态，`measureText` 每帧对每个标签各调一次。

### 4. 没有 `fitView` 能力，初始视角是错的

- 初始 `transformRef = d3.zoomIdentity`（`useGraphCanvas.js:72`），即 `k=1, tx=0, ty=0`；
- 力仿真以"画布中心"为引力中心（`d3.forceCenter(W/2, H/2)`），节点世界坐标分布在
  `(W/2, H/2)` 附近 → **渲染时又被 identity 变换按原样画，图心落在画面中心，看似没问题，
  但一旦图比视口大（>视口尺寸）就必然溢出**，而 `ZOOM_MIN = 0.1` 也无法容纳；
- ControlBar 的"重置视图"（`ControlBar.jsx:handleReset`）只是把变换清成 identity，
  **不是**"缩放到适配全图"，语义与用户预期不符；
- 全项目 grep 无 `fitView` / `zoomToFit`。

### 5. 加载过程中视角完全冻结，新节点从屏幕外生成

`useGraphCanvas.js:render()` 中新增节点的初始位置策略（约 `:966` 起）：

```js
// 沿当前已有节点的包围盒外缘分布，margin = 120
const ringRX = (hasBounds ? (bx1 - bx0) / 2 : W.current / 2) + margin
```

即新节点出生在"已有图的包围盒 + 120px"的大外环上。加上视角不动，
用户看到的是：节点从屏幕边缘外"飘进来"，或者根本没看见（在屏幕外）。
配合 `sim.alpha(0.15).restart()`（热度很低），这些新节点要飘好几百毫秒才就位。

### 6. 进度是"不确定"的，但后端其实已经给了总数

`endpoints/group_graph_store.py:409-410` 响应里已经返回 `nodes_total` / `relations_total`
（首页并行 `_fetch_count`，非首页为 `-1`），而
`frontend/src/lib/graph-api.js:loadGroup()` **完全没读取这两个字段**，
只用了 `nodes/relations/next_*_cursor/*_has_more`。
→ 确定性进度条（已加载 N / 共 M）是**零后端改动**可实现的。

### 7. 每帧 O(E) 次独立 `stroke()`，无绘制批处理

`drawEdges` 里每条边都走完整的 `beginPath → stroke`，箭头单独 `fill`，
标签单独 `roundRect + fill + fillText`。10000 条边 = 10000 次 `stroke()`，
是当前大图卡顿的主因之一。

### 8. 已有但可复用的基础

- 视口裁剪（`drawFrame` 里 `vx0..vy1`）✅
- 四叉树命中（`buildQuadtree`）✅
- 增量保留旧坐标 + 新节点外环出生（`render`）✅
- `node.weight`（1~100，`graph-store.js:459` 由度数 + 可达性算出）✅ ← **这是现成的重要性指标，LOD 直接拿来用**
- 分页节流推送（`PUSH_INTERVAL = 300`）✅

## 三、方案总览

四块能力，互相独立、可分批上线：

| 模块 | 内容 | 优先级 | 改动面 |
|------|------|--------|--------|
| **A. 分级 LOD 与标签系统** | 5 级细节层次 + 密度自适应 + 字号增长 + 标签占位 | P0 | `useGraphCanvas.js`、`constants.js` |
| **B. 相机系统（自动适配）** | `fitView()` + 三套相机策略 + 用户接管 | P0 | `useGraphCanvas.js`、`ControlBar.jsx` |
| **C. 渐进式加载动画** | 五阶段时间线 + 错峰入场 + 确定性进度条 | P1 | `useGraphCanvas.js`、`graph-api.js`、`store.js`、`TopLoadingBar.jsx` |
| **D. 性能预算与降级** | 批量 stroke + measureText 缓存 + reduced 大图模式 | P1/P2 | `useGraphCanvas.js` |

推荐落地顺序：**A0（LOD 常量表）→ B（fitView）→ A1（标签分级）→ C → D**。
先做 B 的收益最直观（"打开就能看见整张图"），A 的量最大，C 最讨喜。

## 四、模块 A：分级 LOD 与标签系统

### 4.1 LOD 分级表

新增常量（`frontend/src/lib/constants.js`）：

```js
/** LOD 分级：按缩放比例 k 划分的细节层次 */
export const LOD_LEVELS = [
  { key: 'far',   min: 0,    max: 0.35 },   // 全景：点云
  { key: 'mid',   min: 0.35, max: 0.75 },   // 中景：圆 + 重要节点标签
  { key: 'near',  min: 0.75, max: 1.40 },   // 近景：完整圆 + 全部标签
  { key: 'close', min: 1.40, max: 2.40 },   // 细节：边标签出现
  { key: 'macro', min: 2.40, max: Infinity },// 微观：全名 + 类型/度数徽标
]
```

每一级的渲染开关（建议写成 `LOD_STYLE` 常量表，绘制函数只读表）：

| 特性 | far | mid | near | close | macro |
|------|-----|-----|------|-------|-------|
| 节点填充 | ✅ | ✅ | ✅ | ✅ | ✅ |
| 节点描边 | ❌ | 1px | 2.5px | ✅ | ✅ + 深色 |
| 节点最小屏幕半径 | 1.2px 钳制 | 1.5px | — | — | — |
| 选中/悬停光晕 | ✅（唯一保留的装饰） | ✅ | ✅ | ✅ | ✅ |
| 节点标签 | ❌ | 仅重要节点（`weight≥70`），截断 6 字 | 全部，截断 8 字 | 截断 16 字 | 全名 |
| 标签底卡（白卡片） | ❌ | ❌ | 仅高亮项 | ✅ | ✅ |
| 边线 alpha / 线宽 | 0.18 / 1px | 0.35 / 1.2px | 0.55 / 1.6px | ✅ 原样 | ✅ 原样 |
| 箭头 | ❌ | ❌ | 仅高亮边 | ✅ | ✅ |
| 边标签 | ❌ | ❌ | 仅高亮/悬停边 | 全部（截断 14） | 全名 |
| 自环 | 退化为小点 | ✅ | ✅ | ✅ | ✅ |

要点：
- **far 级别是"点云模式"**：节点退化为纯色圆点（无描边无标签），边退化为直线。
  这是 10000 节点还能交互的关键。
- 边在 far/mid 级别一律**画直线**（跳过 `bezCp` 的贝塞尔采样），省掉每边两次三角函数 + 除法。
- `ZOOM_MIN` 需从 `0.1` 下调到 **`0.05`**，否则万级节点的 fit 结果会被钳到 0.1 而溢出视口。

### 4.2 密度自适应（本方案的核心增量）

同一 `k` 下，视口内节点越多，标签越该让位。每帧（`drawFrame` 内）计算一次：

```js
// vis 已在 drawFrame 里算好；再统计落在视口内的数量
let vpCount = 0
for (const nd of sortedNodesRef.current) {
  if (nd.x >= vx0 && nd.x <= vx1 && nd.y >= vy0 && nd.y <= vy1 && vis.has(nd.id)) vpCount++
}
const vpAreaK = ((vx1 - vx0) * (vy1 - vy0)) / 1000   // 千世界像素
const density = vpCount / Math.max(1, vpAreaK)
```

密度修正规则（只允许 ±1 级，避免缩放时标签"闪烁跳变"）：

| 条件 | 动作 |
|------|------|
| `density > DENSITY_HIGH (1.20)` | LOD 等级 **-1**（更保守） |
| `density < DENSITY_LOW (0.25)` | LOD 等级 **+1**（更激进），上限 near |
| 其余 | 用 `k` 直接映射的等级 |

再对 `level` 做**迟滞（hysteresis）**：不足上一级阈值 +2% 不回退，防止边界抖动。

### 4.3 字号策略：让放大有反馈

```js
export const LABEL_BASE_PX = 11    // k=1 时的屏幕字号
export const LABEL_GROWTH  = 1.6   // 每 1 倍缩放，屏幕字号增长 px
export const LABEL_MIN_PX  = 10
export const LABEL_MAX_PX  = 20

// 世界坐标字号（绘制前除以 k 只做一次乘法，开销可忽略）
const px = Math.min(LABEL_MAX_PX, Math.max(LABEL_MIN_PX, LABEL_BASE_PX + (k - 1) * LABEL_GROWTH))
const fs = px / k
```

效果对照：

| k | 旧屏幕字号 | 新屏幕字号 |
|---|-----------|-----------|
| 0.3 | 11 | 10.0 |
| 1.0 | 11 | 11.0 |
| 2.0 | 11 | 12.6 |
| 4.0 | 11 | 15.8 |

边标签用同一公式但基准 9px、上限 16px。

### 4.4 标签占位：网格哈希剔除重叠

按 **`weight` 降序**遍历（`sortedNodesRef` 目前是升序，LOD 标签需另建一份降序快照），
用屏幕空间网格做 O(1) 冲突检测：

```js
// 每帧新建，格子边长 ≈ 标签高度（世界坐标 = 14 / k）
const grid = new Map()
const CELL = 14 / k
const tryClaim = (x0, y0, x1, y1) => {
  const gx0 = Math.floor(x0 / CELL), gx1 = Math.floor(x1 / CELL)
  const gy0 = Math.floor(y0 / CELL), gy1 = Math.floor(y1 / CELL)
  for (let gx = gx0; gx <= gx1; gx++)
    for (let gy = gy0; gy <= gy1; gy++) {
      const key = gx * 100000 + gy
      if (grid.has(key)) return false
    }
  for (let gx = gx0; gx <= gx1; gx++)
    for (let gy = gy0; gy <= gy1; gy++) grid.set(gx * 100000 + gy, 1)
  return true
}
```

- 每个标签典型覆盖 2~4 个格子，成本可忽略；
- **选中/悬停节点的标签永远优先占位**（先 claim 它们），不会被挤掉；
- 标签数上限 `MAX_LABELS = 400`（超过即停止 claim），保证极端情况下有界。

### 4.5 `measureText` 缓存

`measureText` 在 Canvas 2D 里是较贵的调用，当前每个节点/边标签每帧都调。
加一层缓存，key 用字体 + 文本，字体变化时整体清空：

```js
const textWCache = new Map()   // `${font}|${text}` -> width
function measure(c, text, font) {
  const key = font + '|' + text
  let w = textWCache.get(key)
  if (w === undefined) {
    if (textWCache.size > 5000) textWCache.clear()
    c.font = font
    w = c.measureText(text).width
    textWCache.set(key, w)
  }
  return w
}
```

### 4.6 边渲染批处理（配合 D 模块）

现在的写法（`drawEdges` 内）：

```js
c.beginPath(); c.lineWidth = ...; c.strokeStyle = ...; c.stroke()   // 每条边一次
```

改为**按桶合批**：把颜色离散为 6 个 alpha 桶 + 3 种线宽 + 3 种颜色（默认/路径红/聚焦蓝），
先把同一桶的边全部 `moveTo/lineTo` 进同一 path，最后每桶一次 `stroke()`：

```js
// 伪代码
const buckets = new Map()   // `${color}|${lw}|${alphaBucket}` -> Path2D 或坐标数组
// 遍历边，push 到桶
// 收尾：for (const [k, b] of buckets) { c.beginPath(); 画完 b; c.lineWidth=...; c.stroke() }
```

预期：10000 边从 10000 次 `stroke()` → 约 20~40 次。箭头同理合批 `fill()`。
注意：`Path2D` 可直接传入 `stroke(path)`，比数组更省一次遍历。

## 五、模块 B：相机系统（加载中是否默认缩放？）

### 5.1 先给出结论

**要缩放，但不是"每来一页缩一次"，而是"首屏框一次 + 之后阻尼软跟随 + 结束时精确框一次"。**

理由：
- 加载时视角纹丝不动 → 新节点在屏幕外生成，用户看到"空白地图慢慢冒点"，体验最差；
- 每页都精确 fit → 相机被反复拉扯，用户会晕（且 LOD 等级反复跳变，标签闪烁）；
- 阻尼软跟随 → 画面像"镜头缓慢拉远把新区域纳入"，这是既有信息量又不眩晕的解。

### 5.2 新增 `fitView()` 能力

```js
/** 将视口适配到可见节点的包围盒 */
const fitView = useCallback((opts = {}) => {
  const {
    padding = 72,        // 世界坐标边距（约等于屏幕上 72k px）
    maxZoom = 1.25,      // 不放大超过此值（单节点图不会糊成巨大圆）
    minZoom = ZOOM_MIN,
    duration = 500,      // 0 表示立即生效
    visibleOnly = true,  // 是否只框选通过筛选的节点
  } = opts
  // 1. 包围盒（含节点半径 r）
  // 2. 空图保护：无节点时直接 return
  // 3. k = clamp(min(W / bw, H / bh), minZoom, maxZoom)
  // 4. 目标变换 t = { x: W/2 - cx*k, y: H/2 - cy*k, k }
  // 5. duration > 0 → animateTo(t, duration)，否则直接赋值 + scheduleRender()
}, [])
```

`animateTo` 用 `requestAnimationFrame` + `d3.easeCubicOut` 同时插值 `x/y/k`
（不要用 `d3.interpolateZoom`，后者先缩后移的观感在"框选整图"场景下反而突兀）：

```js
const animateTo = (t, duration) => {
  cancelCameraAnim()
      if (rafId.current) cancelAnimationFrame(rafId.current)
      if (cameraAnimRef.current) cancelAnimationFrame(cameraAnimRef.current)
      if (heatTimerRef.current) clearTimeout(heatTimerRef.current)
      if (firstFitTimerRef.current) clearTimeout(firstFitTimerRef.current)
  const from = { ...transformRef.current }
  const start = performance.now()
  const step = (now) => {
    const p = Math.min(1, (now - start) / duration)
    const e = d3.easeCubicOut(p)
    transformRef.current = d3.zoomIdentity
      .translate(from.x + (t.x - from.x) * e, from.y + (t.y - from.y) * e)
      .scale(from.k + (t.k - from.k) * e)
    setZoom(transformRef.current.k)
    scheduleRender()
    if (p < 1) cameraAnimRef.current = requestAnimationFrame(step)
    else cameraAnimRef.current = null
  }
  cameraAnimRef.current = requestAnimationFrame(step)
}
```

**用户接管**：在 `onWheel` / `onPtrDown` 开头调用 `cancelCameraAnim()` 并置
`userOverrodeCamera.current = true`，此后本次加载周期内不再自动移动相机
（提供"适配视图"按钮可手动恢复自动态）。

### 5.3 三套策略对比

| 策略 | 行为 | 优点 | 缺点 | 结论 |
|------|------|------|------|------|
| **A 仅首屏** | 第一页到达后 400ms fit 一次，后续不再动 | 实现最简、零抖动 | 加载中后段新节点仍在屏外出生 | 可作为降级方案 |
| **B 每页 fit** | 每页数据到达都精确 fit | 内容始终占满 | 相机反复拉扯 + LOD 抖动，300ms 一页时几乎不可用 | ❌ 不采用 |
| **C 阻尼软跟随** ⭐ | 首屏 fit；加载期间每帧向目标相机插值 6%；结束后 600ms 精确 fit | 顺滑、内容不丢、无抖动 | 需要逐帧驱动（与入场动画共用 rAF） | ✅ **推荐** |

**策略 C 的详细时机表**：

| 时机 | 动作 |
|------|------|
| 第一页数据 `render()` 完成 + 80ms | `fitView({ duration: 480, maxZoom: 1.25 })` — 让用户立刻看到内容 |
| 加载中每次 `updateGraphData()`（`isLoadingData === true`） | 重算包围盒（用 **95 分位** 而非极值，剔除离群点），设为软跟随目标 |
| 加载中每帧 | `cam.x += (target.x - cam.x) * 0.06`（k 同理），仅当偏差 > 2px 时生效 |
| 全部加载完成 + 权重计算完成（`skipWeights = false` 之后） | `fitView({ duration: 600, maxZoom: 1.25 })` 精确收尾 |
| 任意时刻用户滚轮/按下 | `userOverrodeCamera = true`，停止自动相机 |

### 5.4 新节点出生位置（与加载动画强耦合）

当前"大外环 + margin 120"的策略在软跟随时依然会溢出视口。改为三级优先：

1. **有边连到已有节点** → 出生在邻居位置 + 半径 40 世界像素的随机偏移（"从邻居处发芽"）。
   这是视觉最自然的一种，且仿真几乎不用收敛就能就位。
2. **无边但图已存在** → 出生在**当前视口中心**半径 `min(W,H) * 0.35 / k` 的世界圆内（黄金角分布）。
   用户看到的是"节点在画面中央聚拢展开"，而不是"从屏幕外飞入"。
3. **首屏（无任何已有节点）** → 出生在视口中心的小圆内（半径 `min(W,H) * 0.25`），
   让第一次 fit 之前的 80ms 里内容就在画面中间。

伪代码改动点在 `render()` 中替换 `ringX/ringRX` 那一段：

```js
const newNodes = safeN.filter((n) => !prevIds.has(n.id))
// 邻居索引：safeL 里 target/source 落在旧集合中的边
const seedOf = new Map()   // newId -> [{x,y}]
// 1) 有邻居：取邻居平均坐标 + 抖动
// 2) 无邻居：视口中心环
```

## 六、模块 C：渐进式加载动画

### 6.1 五阶段时间线

```
t=0        加载开始
  │  ┌─ 阶段0 骨架：画布中央微脉冲 + 顶部不定进度条淡入
t≈200ms   第一页到达（300 节点）
  │  ├─ 阶段1 入场：节点从视口中心/邻居处错峰弹出（错开 12ms，总 ≤260ms）
  │  └─ 阶段2 相机：fitView 480ms（让内容立刻铺满）
t=200~n s 后续页陆续到达
  │  ├─ 阶段1' 每页重复错峰入场
  │  ├─ 阶段2' 相机软跟随（6%/帧）
  │  └─ 阶段3 进度条推进（nodes_total 已知 → 确定性）
t=最后页
  │  ├─ 阶段4a 权重计算（skipWeights=false，可能 100ms~1s）
  │  ├─ 阶段4b fitView 600ms 精确收尾
  │  └─ 阶段4c 进度条 100% → 800ms 渐隐；status 显示总数
```

### 6.2 入场动画实现

节点对象在 `render()` 里打时间戳：

```js
// 只给"本次新增"的节点打戳，错峰 12ms，上限 240ms
n.appearAt = baseTime + Math.min(newIdx * 12, 240)
```

`drawNodes` 里换算到透明度与半径：

```js
const ap = nd.appearAt ? Math.min(1, (now - nd.appearAt) / 260) : 1
if (ap < 1) animatingRef.current = true          // 保活标记
const ease = 1 - Math.pow(1 - ap, 3)             // easeOutCubic
const rDraw = BR * (0.45 + 0.55 * ease)          // 半径 45% → 100%
c.globalAlpha *= ease                            // 与现有 alpha 逻辑相乘，不要覆盖
```

两个关键点：
1. **`c.globalAlpha *= ease`** —— 必须在现有"路径高亮/聚焦"的 alpha 计算**之后**相乘，
   否则会破坏已有的调光逻辑；
2. **rAF 保活**：入场动画期间仿真可能已停（`alpha` 衰减到 0），`scheduleRender` 的
   `needRender` 守卫会让画面冻在半透明状态。需要在 `drawFrame` 末尾补：

```js
if (animatingRef.current) {
  animatingRef.current = false   // 下帧重算
  rafId.current = requestAnimationFrame(drawFrameRef.current)
}
```

### 6.3 进度可视化（零后端改动）

`graph-api.js:loadGroup()` 现在丢弃了总数，改为透传：

```js
// 第一页
if (d.nodes_total >= 0) onProgress?.({ loaded: loadedNodes, total: d.nodes_total, page: pg })
// 之后每页
else onProgress?.({ loaded: loadedNodes, total: -1, page: pg })
```

- `store.js` 新增 `loadProgress: { loaded, total, page }`；
- `TopLoadingBar.jsx` 改为：`total > 0` 时显示**确定性进度条**
  （宽度 = `loaded/total`，右侧显示 `1,240 / 3,500 节点 · 第 5 页`）；
  `total < 0` 时回退为现有转圈 + "已加载 N 节点"；
- 进度条建议插值平滑（`transition: width 300ms ease-out`），避免每页跳一大格。

### 6.4 仿真热度统一管理

现在有三处独立调用 `alpha/alphaTarget`，容易互相踩（拖拽中加载新页会把拖拽热度顶掉）。
建议收敛为一个入口：

```js
const heat = useCallback((target, ms = 0) => {
  const sim = simRef.current
  if (!sim) return
  sim.alphaTarget(target).restart()
  if (ms) heatTimerRef.current = setTimeout(() => sim.alphaTarget(0), ms)
}, [])
```

- 新增数据 → `heat(0.30, 300)`（比现在的 `alpha(0.15)` 收敛更快，节点不至于长时间乱飘）
- 拖拽开始 → `heat(0.30)`；拖拽结束 → `heat(0)`
- 权重重算/筛选变化 → `heat(0.15, 200)`

### 与方案的差异（实现时调整）

1. **相机软跟随改为有界缓动**：原方案是"每帧向目标阻尼插值 6%"，实现时改为"数据更新后缓动 420ms 到位"。
   原因是逐帧阻尼会让渲染循环在整个加载期间持续 60fps 重绘，万级节点下代价过高；
   有界缓动保留同样的顺滑观感，但只在动画窗口内重绘。
2. **中景（mid）不再按 `weight` 阈值筛选标签**：原方案的 `weight >= 70` 在真实数据上过于苛刻
   （`weight` 由度数 + 可达性算出，多数节点达不到），会出现"中景一个标签都没有"。
   改为 `LOD_NODE_LABEL = [none, all, all, all, all]`，中景靠更大的 `labelCell`（26 vs 14）自然稀疏化。
3. **进度条按「节点 + 关系」总条目加权**：节点与关系是各自独立分页推进的，只按节点总数会在
   节点加载完、关系仍在加载时把进度条显示成 100%。

### 缺陷修复记录

1. **低 LOD 下悬停/选中的标签被一起隐藏**（用户反馈）：`drawNodes` 标签趟与 `drawEdgeLabels`
   在 `mode === 'none'` 时直接 `return`，导致用户主动关注的节点/关系也没有标签。
   改为：相关节点/关系**无视 LOD** 强制显示；节点标签分三轮（核心 → 邻居 → 其余），
   核心节点优先占位，避免被邻居标签挤掉。
2. **选中节点后悬停非邻居节点不显示标签**（用户反馈）：`onPtrMove` 中"选中后仅关注邻居"的逻辑
   会把 `hoveredNodeId` 置空，悬停信息整体丢失。新增 `hoveredRawRef` 记录**未经过滤的原始悬停节点**，
   仅用于标签显示与关系标签判定，不改变原有的调光/聚焦语义。
3. **（关键）鉴权门导致 canvas 事件监听器从未绑定**（用户反馈「悬浮/点击/拖动/滚轮全部失效」）：
   `App` 在 `authState !== 'ready'` 时 `return <PasswordGate />`，**首次渲染时 `<canvas>` 根本不存在**；
   而事件绑定的 `useEffect` 依赖的是一组引用稳定的 `useCallback`（`onWheel`/`onPtrMove`/…），
   挂载后依赖不再变化、effect 不会重跑，于是监听器被绑到一个 `null` 上且永不重试。
   这与「是否加载完成」无关，因此表现为从头到尾都无交互；也连带让加载遮罩的滚轮转发失去意义
   （转发到 canvas 后没有任何监听器）。
   修复：`App` 用**回调 ref** 把 canvas 元素本身提升为状态（`canvasEl`）并传给 `useGraphCanvas`，
   绑定 effect 改为依赖该元素——元素挂载后立即完成绑定；`canvasRef` 仍照常维护。
   该缺陷由 v0.0.91 的密码门改造引入，与本次显示优化无关。
4. **悬停时仍有部分关联节点标签不显示**（用户反馈）：相关节点只是「优先占位」，
   仍受标签占位网格约束——位置相近的邻居一旦撞位就被静默 `return` 掉。
   修复：核心节点与其邻居的标签改为**强制绘制**（撞位也画），绘制顺序调整为
   「普通 → 邻居 → 核心」使鼠标指到的标签永远在最上层；有聚焦时不再绘制普通标签，
   把 `MAX_LABELS` 的额度与画面空间都留给关联节点；高亮边标签同样改为强制绘制。
